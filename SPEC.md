# Спека v2: интерактивный курс «Linux за 2 месяца» (локальный сайт)

## v3 (актуально): весь сайт как терминал + concept-first

### Весь сайт = терминал (образец: kitty пользователя)

Эталон — реальный конфиг `~/.config/kitty/kitty.conf` + `~/.config/kitty/catppuccin-mocha.conf`:
Catppuccin Mocha (дефолтная тема сайта), JetBrainsMono (моно ВЕЗДЕ, включая текст урока),
полупрозрачность фона ~0.9 (лёгкая), отступы ~10px, без «карточек» и декораций,
**powerline-вкладки снизу (slanted)** как навигация по модулям. Урок — это «сессия
терминала»: заголовки как комментарии/промпты, навигация в стиле
`user@linux:~$ cd курс/модуль-1/01-что-такое-linux`, roadmap как вывод `tree`,
квизы как `[?]`-вопросы, онбординг как login-секвенция. Остальные 7 тем остаются,
но дефолт — Mocha из kitty. Лигатуры включить (`font-feature-settings "liga"`).

### Concept-first (запрет «команда раньше понятия»)

Любая команда впервые появляется в курсе ТОЛЬКО после того, как объяснены:
(a) само понятие, к которому она относится, — через быт Windows/macOS;
(b) зачем это читателю лично (какую боль решает). Конкретно:
- «Пользователь» в Linux (у каждого своё, файлы/процессы имеют владельца; в Windows
  дома чаще один пользователь — «ты») объясняется в уроке 01 ДО `whoami`;
- ядро (зачем знать «какой двигатель») — до `uname`;
- память и диски (почему место кончается, кто его ест) — до `free`/`df` (урок 02
  дистрибутивы: команды убрать или дать только как «если Linux уже стоит — проверь»).
Правило аудита для всех 40 уроков: первое вхождение каждой команды проверяется
на «понятие до команды»; нарушения — точечно патчить.

## Цель

Курс для взрослых новичков (андрагогика): 8 модулей × 5 уроков, урок = ~30 минут,
день = 1 урок, за ~2 месяца — уверенный уровень терминального Linux. Основан на
шпаргалке `/tmp/opencode/linux-cheatsheet-src/README.md` (MIT) + существующих уроках
в `content/lessons/` (старые id — источник материала, при интеграции будут удалены).
Статический сайт: ванильный HTML/CSS/JS, офлайн, без сборки.

## Педагогический шаблон урока (обязательный порядок секций)

1. `## Зачем это тебе` — реальная жизненная ситуация/боль, ради чего 30 минут
2. `## Как это работает` — разжёвано. Новые понятия объяснять **через знакомое из
   Windows/macOS** («как Проводник, только...»). Первые модули — максимально подробно
   (что делает каждая буква команды, что будет без флага), к модулю 8 темп выше.
   Показывать типичные ошибки и как читать текст ошибки.
3. `## Попробуй` — 1–5 блоков ```terminal (с урока 01 включительно)
4. `## Проверь себя` — 2–4 блока ```quiz
5. `## Итог дня` — чек-лист 3–5 пунктов («сейчас ты умеешь…»)
6. `## Домашка` — опционально: что сделать на своей реальной машине (если не симулируется)
7. `<details><summary>🤓 Для любопытных</summary>` — глубокая теория, сворачивается

Тон: русский, на «ты», без канцелярита, короткие абзацы. Никакой стены таблиц:
таблицы ≤ 10 строк. Опасное (rm -rf /, mkfs, реальные kill чужих процессов) — только
в тексте с предупреждениями, в terminal-задачи не включать.

## Попробуй

```terminal
{
  "title": "...",
  "task": "...",
  "shell": "bash",
  "setup": { "cwd": "/home/user", "tree": { "README.txt": "Привет!\n", "docs": {} } },
  "check": [ { "type": "path_exists", "path": "/home/user/projects" } ],
  "solution": ["mkdir projects"],
  "hint": "..."
}
```
````

- `shell` — необязательное поле: `"bash"` (дефолт) | `"fish"` | `"zsh"`.
  Уроки 23–25 используют fish/zsh-режимы хотя бы в одной задаче для наглядности.
- `setup.tree`: строка = файл (содержимое), объект = папка; корень = `/home/user`.
- JSON обязан парситься; quiz — тот же формат, что раньше (question/options/answer/explanation).
- Домашка не должна требовать симулятор — это то, что человек делает у себя.

## Симулятор v2

Всё из v1 (см. git-историю SPEC) плюс:

- **Режимы оболочки** (`shell` в блоке): промпт bash `user@linux:~$`, fish
  `user@linux ~>`, zsh `~/ ❯` (точный вид на усмотрение дизайнера, но различимый и
  подписанный в help). В режиме fish — серая ghost-автоподсказка из истории команд
  (Tab принимает), как в настоящем fish.
- **Новые команды** (canned, для задач модулей 4 и 6): `ps` (реалистичный вывод с
  PID 412 `sleep`, 780 `bash`, 913 `firefox` и т.п.), `kill <PID>` (успех только для
  PID из вывода ps; иначе ошибка как в bash), `ping <host>` (canned 4 строки ICMP +
  статистика; без Ctrl+C), `curl <url>` (canned маленький HTML). `free -h`, `df -h`,
  `uname -a` сохраняют контракт: free содержит `total`, uname содержит `Linux`,
  man-страницы содержат имя команды.
- Задачи в контенте могут использовать ТОЛЬКО команды из этого набора (v1 + v2).
  systemctl/ssh/scp/cron/nano в симуляторе НЕТ — для них quiz/текст/домашка.
