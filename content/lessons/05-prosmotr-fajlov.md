Файл в терминале читается сверху, снизу или по частям. Ниже — четыре инструмента, которые покрывают 95% случаев.

## Показать целиком

```bash
cat notes.txt        # вывести весь файл
```

`cat` — короткий и простой, но осторожен с большими файлами: он честно вывалит все мегабайты в окно. Для логов лучше подойдут другие команды.

## Посмотреть начало или конец

```bash
head -n 20 app.log   # первые 20 строк
tail -n 20 app.log   # последние 20 строк
```

Зачем это нужно? В конфигах шапка рассказывает, что за файл. В логах самое свежее — всегда внизу, поэтому `tail` там главный герой.

## Посчитать

```bash
wc -l notes.txt      # сколько строк
wc -w notes.txt      # сколько слов
```

## Записать в файл

Если поставить `>` после команды, её вывод уйдёт не на экран, а в файл:

```bash
echo "Привет" > hello.txt     # создать файл с текстом (старое содержимое затрётся)
echo "Ещё строка" >> hello.txt  # дописать в конец
```

Разница между `>` и `>>` — критичная. Одна стрелка **перезаписывает** файл, две — **дописывают**. Перепутаешь — потеряешь содержимое.

> 💡 Настоящий лайфхак: `tail -f app.log` следит за файлом в реальном времени и показывает новые строки по мере появления. Для живого сервера — незаменимо.
