## Зачем это тебе

До сих пор каждая команда работала сама по себе, а её вывод просто появлялся на экране. Но настоящая сила терминала — в том, что вывод одной команды можно **передать** другой или **записать в файл**.

Зачем? Смотри: нужно найти ошибки в логе. Ты уже умеешь это через `grep "error" app.log`. А если нужно посчитать, сколько таких строк? Можно сделать это одной цепочкой: «прочитать файл → отфильтровать ошибки → посчитать строки». Три маленькие команды, соединённые вместе, дают одну большую. Это и называется конвейер.

## Как это работает

### Три канала у каждой команды

У каждой команды есть три «двери», через которые проходит текст:

```
              ┌──────────┐ ──▶ 1 stdout (обычный результат)
 0 stdin ──▶  │ команда  │
              └──────────┘ ──▶ 2 stderr (сообщения об ошибках)
```

- **stdin (0)** — вход: откуда команда берёт данные.
- **stdout (1)** — обычный вывод: результат работы.
- **stderr (2)** — вывод ошибок.

Обычно stdin — это клавиатура, а stdout и stderr идут на экран. Перенаправления позволяют переставить эти потоки куда угодно.

### Записать вывод в файл: > и >>

```bash
echo "Привет" > hello.txt      # создать файл с текстом (перезаписать)
echo "Ещё строка" >> hello.txt # дописать в конец
```

Один символ `>` означает «направь stdout не на экран, а в файл». Два символа `>>` — «допиши в конец».

Разница **критична**:

- `>` **перезаписывает** файл: было содержимое — стало новое, старое стёрто.
- `>>` **дописывает** в конец, старое остаётся.

Перепутал — потерял содержимое файла. Если файла с таким именем не было, `>` его создаст.

Проверить результат можно так: `cat hello.txt`.

### Соединить команды: |

Вертикальная черта `|` называется **пайп** (труба). Она берёт stdout левой команды и подаёт его на stdin правой:

```bash
cat app.log | grep "error"
```

Читается: «прочитать app.log и передать его содержимое команде grep, чтобы та отфильтровала строки со словом error». `grep`, получив данные на вход, работает точно так же, как с файлом-аргументом.

Так можно строить длинные цепочки:

```bash
cat app.log | grep "error" | wc -l     # прочитать → отфильтровать ошибки → посчитать строки
```

Слева направо: `cat` отдаёт текст, `grep` оставляет только строки с error, `wc -l` считает, сколько их. Каждая команда маленькая и делает одну вещь — а вместе получается ответ на сложный вопрос.

### Ещё несколько полезных знаков

| Знак | Что делает |
|---|---|
| `cmd > file` | stdout в файл (перезаписать) |
| `cmd >> file` | stdout в файл (дописать) |
| `cmd1 \| cmd2` | вывод первой на вход второй |
| `cmd1 && cmd2` | вторая — только если первая успешна |
| `cmd 2> err.log` | вывод ошибок в файл |
| `cmd > /dev/null` | выбросить вывод в «чёрную дыру» |

Последнее — `/dev/null` — виртуальный файл, который принимает всё и ничего не хранит. Полезно, когда вывод не нужен.

По умолчанию `>` и `|` работают только с **обычным** выводом (stdout). Ошибки (stderr) идут отдельно, на экран, — поэтому их перенаправляют через `2>`.

> 💡 Типичная ошибка: `>` вместо `>>`. Ты хотел добавить строку в конец, а стёр весь файл. Запомни: **две стрелки — дописать**, одна — перезаписать. Сомневаешься — сначала `cat`, потом пиши.

## Итог дня

- **Ты понимаешь**, что у команды есть вход (stdin) и два выхода (stdout и stderr).
- **Ты умеешь** записывать вывод в файл через `>` и дописывать через `>>`.
- **Ты знаешь**, что `>` перезаписывает файл, а `>>` нет — и это разные вещи.
- **Ты умеешь** строить конвейеры из нескольких команд через пайп `|`.
- **Ты собрал** свой первый трёхступенчатый конвейер: `cat | grep | wc -l`.

## Домашка

1. На своём компьютере создай файл и запиши в него пару строк: сначала через `echo "первая" > test.txt`, потом через `echo "вторая" >> test.txt`. Проверь результат через `cat test.txt` — там должно быть две строки.
2. Возьми любой настоящий лог или текстовый файл и построй конвейер: посчитай, сколько в нём строк с каким-нибудь словом, через `cat файл | grep слово | wc -l`.
3. Попробуй цепочку из урока поиска: `grep -n "слово" файл | head -n 3` — она покажет только первые три найденные строки с номерами. Подставь свои слова.

<details><summary>🤓 Для любопытных</summary>

**Философия Unix.** Идея конвейеров родилась в 1970-х вместе с Unix и звучит так: «делай одну вещь и делай её хорошо». Вместо одной огромной программы, которая умеет всё, — много маленьких, которые умеют по одному делу, но легко соединяются. Пайп — это клей между ними. Вся командная строка Linux построена на этом принципе.

**Почему stderr отдельно.** Сделано специально: ты можешь записывать результат работы в файл, а ошибки — видеть на экране. Часто их сливают вместе: `cmd > out.log 2>&1` («stdout в файл, и stderr туда же»). Внимательно с порядком: `2>&1` должен идти **после** `>`.

**Коды возврата.** За знаком `&&` спрятан механизм: каждая команда по завершении возвращает число — `0` значит «успех», всё остальное «ошибка». `cmd1 && cmd2` запустит вторую только если первая вернула `0`. Проверить код последней команды можно через `echo $?`. На этом строятся умные скрипты.

**`<` — вход из файла.** Есть и обратное перенаправление: `wc -l < list.txt` подаёт файл на stdin команде. Результат похож на `wc -l list.txt`, но без имени файла в выводе — иногда это удобнее.

**`$(...)` — подстановка вывода.** Если написать `echo "сегодня $(date)"`, оболочка сначала выполнит `date`, а её вывод подставит прямо в строку. Так команды можно вкладывать друг в друга без пайпов.

</details>
