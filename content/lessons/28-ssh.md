## Зачем это тебе

Почти любой сервер в мире — это машина без монитора и клавиатуры, к которой подключаются по сети. Приехать к ней нельзя, зато можно войти по **SSH**: получить терминал удалённого компьютера прямо в своём окне. Если ты арендуешь дешёвый VPS за пару долларов в месяц (или у тебя есть домашний сервер/роутер с OpenWrt), SSH — это то, что откроет тебе дверь. Правильно настроенный ключ вместо пароля — и тебя перестанут подбирать боты.

## Как это работает

### Что такое SSH

**SSH** (Secure Shell) — шифрованный туннель к другому компьютеру. Ты набираешь команды у себя, они выполняются там, а обратно едет вывод. Всё содержимое туннеля зашифровано, поэтому даже в открытом Wi-Fi кафе пароль и команды не видны посторонним. По ощущениям — как Просмотрщик удалённого рабочего стола, только текстовый и без графики.

```bash
ssh user@host                 # подключиться к серверу host под пользователем user
ssh -p 2222 user@host         # если SSH повесили на нестандартный порт
ssh user@host 'df -h'         # выполнить одну команду удалённо и выйти
```

При первом входе SSH покажет **отпечаток ключа сервера** и спросит, доверяешь ли ты ему. После согласия хост записывается в `~/.ssh/known_hosts`. Если в следующий раз отпечаток изменится, SSH поднимет тревогу: возможно, тебя перенаправляют на поддельный сервер.

### Пароль или ключ — что выбрать

Пароль можно подобрать перебором, ключ — практически нет. Поэтому на серверах вход по паролю отключают.

**Ключ** — это пара файлов:

- **Приватный** (`~/.ssh/id_ed25519`) — твой личный. Не отдаёшь никому и никогда. Права `600`.
- **Публичный** (`~/.ssh/id_ed25519.pub`) — его кладут на сервер. Отдавать можно всем.

Аналогия простая: приватный ключ — ключ от замка, публичный — сам замок. Ты приносишь на сервер замок, а ключ держишь при себе.

```bash
ssh-keygen -t ed25519 -C "me@mail"   # создать пару ключей
ssh-copy-id user@host                # отправить публичный ключ на сервер
```

После этого `ssh user@host` пускает без пароля — сервер сам проверит, что у тебя есть подходящий ключ.

### Файл ~/.ssh/config — короткие имена

Чтобы не набирать длинную строку с портом и ключом, опиши сервер один раз:

```
Host prod
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/prod_ed25519
```

Теперь достаточно `ssh prod`. Такие файлы есть у каждого, кто работает с несколькими серверами.

> ⚠️ Публикуя конфиги и скрипты, стирай из них адреса, логины и пути к ключам. Приватные ключи в git не попадают никогда.

## Домашка

Раз уж SSH в симуляторе нет — потренируйся по-настоящему. Своя машина или самый дешёвый VPS (у большинства провайдеров есть тариф за 1–3 $ в месяц):

1. Сгенерируй ключ: `ssh-keygen -t ed25519 -C "me@mail"`. Задай парольную фразу.
2. Посмотри, что появилось: `ls -la ~/.ssh`. Проверь права: каталог `700`, приватный ключ `600`.
3. Скопируй ключ на сервер: `ssh-copy-id user@сервер`. Войди вторым окном — пароль уже не спросят.
4. Только **после успешного входа по ключу** отключи пароли: в `/etc/ssh/sshd_config` поставь `PasswordAuthentication no`, затем `sudo sshd -t && sudo systemctl reload ssh`.
5. Заведи в `~/.ssh/config` алиас и ходи одной командой: `ssh prod`.

> 🔴 Не закрывай текущую SSH-сессию, пока не проверишь вход **в новом окне**. Иначе можно потерять доступ к серверу.

## <details><summary>🤓 Для любопытных</summary>

- **ssh-agent** держит расшифрованный ключ в памяти: `eval "$(ssh-agent -s)"` и `ssh-add ~/.ssh/id_ed25519` — парольную фразу спрашивают один раз за сессию.
- **Проброс портов**: `ssh -L 8080:localhost:80 user@host` откроет твой локальный `8080` как удалённый `80` — способ заглянуть в службу, закрытую наружу. `ssh -D 1080 user@host` — SOCKS-прокси.
- **Прыжок через бастион**: `ssh -J jump@bastion user@internal`, или блок `ProxyJump` в конфиге.
- В `~/.ssh/authorized_keys` можно ограничить ключ: `from="10.0.0.0/8",command="/bin/ls" ssh-ed25519 AAA…`.
- Двухфакторная аутентификация для SSH: `AuthenticationMethods publickey,keyboard-interactive` плюс `libpam-google-authenticator`.
</details>
