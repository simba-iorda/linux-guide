## Зачем это тебе

Рано или поздно ты увидишь это:

```
cat: secret.txt: Permission denied
```

Файл существует, ты его видишь — а прочитать не можешь. Или копируешь скрипт с интернета, запускаешь, а он отвечает `Permission denied` просто потому, что не помечен как «исполняемый».

Разгадка всегда в одном месте: у каждого файла есть **владелец** и **набор из девяти флажков**. `ls -l` показывает их в начале строки. Как только ты научишься эту строку читать, `Permission denied` перестанет быть загадкой — ты будешь точно знать, чего не хватает.

## Как это работает

Возьми вывод `ls -l`:

```
-rwxr-xr--  1  alice  devs  4096  Sep 23 10:00  script.sh
│└┬┘└┬┘└┬┘       └─┬─┘  └┬─┘
│ │  │  │          │     └── группа файла: devs
│ │  │  │          └──────── владелец файла: alice
│ │  │  └───────────────── остальные: r--  (только читать)
│ │  └──────────────────── группа:    r-x  (читать и выполнять)
│ └─────────────────────── владелец:  rwx  (всё)
└───────────────────────── тип: - файл, d папка, l ссылка
```

Первые девять символов после типа — это три тройки: **владелец**, **группа**, **остальные**. В каждой тройке три позиции: `r`, `w`, `x`.

Проверка прав идёт **по порядку**: сначала ядро смотрит, не владелец ли ты, потом — не в группе ли, и только потом применяет «остальных». Срабатывает первая подходящая категория, дальше не смотрится.

Аналогия с квартирой: владелец может всё, члены семьи (группа) — часть возможностей, гости (остальные) — только то, что им разрешили. И, как с ключом от подъезда, право `x` — это «можно войти».

**Для файла и для папки `rwx` значат разное:**

| Право | Для файла | Для папки |
|:---:|---|---|
| `r` | читать содержимое | видеть список файлов |
| `w` | изменять содержимое | создавать, удалять, переименовывать файлы внутри |
| `x` | запускать как программу | войти в неё (`cd`) и обращаться к файлам |

Запомни главное про папки: без `x` ты не попадёшь внутрь, даже если у папки есть `r`. А про удаление есть контринтуитивная тонкость: чтобы удалить файл, права на *сам файл* не нужны — достаточно права `w` на папку, где он лежит. Поэтому в общей папке `/tmp` стоит особый sticky-бит: удалить там можно только своё.

**Буквы в числа** — это просто сумма:

| Буквы | Число | Смысл |
|:---:|:---:|---|
| `rwx` | 7 | всё |
| `rw-` | 6 | читать и писать |
| `r-x` | 5 | читать и выполнять |
| `r--` | 4 | только читать |
| `---` | 0 | ничего |

Отсюда `644` (обычный файл), `755` (скрипт или папка), `600` (секрет, только мне). Как выдавать эти права — в следующем уроке.

**Как читать ошибку.** `Permission denied` почти всегда означает одно из трёх: нет `r` на файл, нет `x` на папку по пути к нему или нет `x` на самом файле, если ты пытаешься его запустить. Отдельный случай — `Operation not permitted`: это про смену владельца, там правит только root.

## Итог дня

Сейчас ты умеешь:

- читать право-строку из `ls -l`: тип, владелец, группа, остальные;
- объяснять разницу между `r`, `w`, `x` для файла и для папки;
- называть, в каком порядке ядро проверяет права;
- перевести буквы в число (r=4, w=2, x=1) и узнавать частые комбинации 644/755/600;
- понимать, что значит `Permission denied`, и искать причину именно в правах.

## Домашка

Всё делается на своей машине, команды только читают.

1. Посмотри права своей домашней папки: `ls -la ~`. У большинства папок будет `drwxr-xr-x`, у конфигов вроде `.bashrc` — `-rw-r--r--`.
2. Загляни в общую папку: `ls -ld /tmp`. Обрати внимание на права `drwxrwxrwt` — последняя буква `t` и есть sticky-бит.
3. Посмотри системный файл с паролями: `ls -l /etc/shadow`. Ты увидишь `-rw-r-----` и владельца root: он закрыт даже от группы.
4. Своими глазами увидь ошибку: создай папку с секретом и попробуй прочитать файл чужого пользователя, например `cat /etc/shadow` (без sudo). Получишь `Permission denied` — теперь ты точно знаешь, откуда она берётся.
5. Найди в системе папку без права на запись: `ls -ld /`. Сравни с `ls -ld ~`: у домашней папки ты владелец и можешь писать, у корня — нет.

## <details><summary>🤓 Для любопытных</summary>

Кроме девяти обычных битов есть три особых. Меняют их командой `chmod` (*change mode*, «сменить режим») — подробно о ней в следующем уроке. **SUID** (`chmod u+s`, `4xxx`): программа запускается с правами владельца файла — так `/usr/bin/passwd` может писать в `/etc/shadow`, оставаясь доступным обычным людям. **SGID** (`g+s`, `2xxx`) на папке: новые файлы автоматически наследуют группу папки — спасает в общих проектных каталогах. **Sticky** (`+t`, `1xxx`): в папке удалять файлы может только владелец — это и есть `/tmp` с `drwxrwxrwt`.

Права из девяти битов — не единственный способ. Есть списки доступа **ACL**: `setfacl -m u:bob:rw file` даёт права конкретному человеку, `getfacl file` показывает список. Полезно, когда «владенец/группа/остальные» — слишком грубо.

Откуда берутся права у новых файлов? Из **umask** — маски, которая вычитается из «всем всё». Обычная маска `022` превращает `666` в `644` для файлов и `777` в `755` для папок. Посмотреть: `umask`.

Хорошая привычка при разборе: `namei -l /path/to/file` покажет права на каждом шаге пути — сразу видно, где именно спрятался запрет.

</details>
