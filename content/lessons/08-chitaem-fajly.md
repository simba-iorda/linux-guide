## Зачем это тебе

Файл в терминале не открывается двойным щелчком. Ты пишешь команду — и текст появляется прямо в окне. Иногда это удобнее редактора: не нужно ничего открывать, а можно сразу «вытащить» нужный файл, сложить его с другим или посмотреть, что записалось в лог минуту назад.

Ключевой вопрос — **сколько** файла тебе нужно. Целиком, только начало, только конец или вообще посчитать строки? Для каждого случая есть своя команда.

## Как это работает

### Показать целиком: cat

```bash
cat notes.txt        # вывести весь файл на экран
cat a.txt b.txt      # вывести два файла один за другим
```

`cat` — сокращение от **con**catenate, «сцепить». Она не только показывает один файл, но и склеивает несколько: выводит их содержимое подряд, в порядке аргументов.

Главная осторожность: `cat` честно вываливает файл целиком. Для текста на пару страниц это нормально, а вот `cat` на лог в 500 мегабайт зальёт экран так, что будешь долго листать вверх. Для больших файлов есть команды ниже.

### Посмотреть начало: head

```bash
head -n 20 app.log   # первые 20 строк
head -n 5 notes.txt  # первые 5 строк
```

`head` переводится «голова». Флаг `-n` задаёт число строк (от **number**). Без `-n` по умолчанию показываются 10 строк.

Зачем это нужно: в конфигах и логах начало файла часто объясняет, что это вообще за файл — заголовок, версия, настройки по умолчанию.

### Посмотреть конец: tail

```bash
tail -n 20 app.log   # последние 20 строк
```

`tail` — «хвост». Тот же флаг `-n`, только строки берутся с конца.

Это **главный герой** при работе с логами. В логах самое свежее всегда дописывается внизу, поэтому когда что-то сломалось десять секунд назад — нужен `tail`, а не `head`.

Есть ещё волшебный ключ `-f` (follow): `tail -f app.log` показывает файл и не закрывается, а дописывает новые строки по мере появления. Настоящий монитор логов в реальном времени. В тренажёре он не нужен, но на живом сервере — незаменим.

### Посчитать: wc

```bash
wc -l notes.txt      # сколько строк
wc -w notes.txt      # сколько слов
wc -c notes.txt      # сколько байт
```

`wc` — **w**ord **c**ount, «счёт слов», но умеет и строки (`-l`, lines), и байты (`-c`). Без флагов выводит все три числа сразу. Чаще всего нужен `-l`: «сколько строк в логе», «сколько записей в списке».

### Постраничный просмотр: less

```bash
less big_file.txt
```

`less` открывает файл как «читалку»: листаешь стрелками или пробелом, ищешь по тексту клавишей `/слово`, выходишь клавишей `q`. Внутри неё можно листать файл любого размера — память она не забивает. В тренажёре `less` не поддерживается (это интерактивная программа), но в настоящем терминале это твой главный инструмент для больших файлов.

> 💡 Как выбрать команду: маленький файл — `cat`; большой — `less`; нужен заголовок — `head`; свежие данные из лога — `tail`; нужно число строк — `wc -l`.

## Итог дня

- **Ты умеешь** показать файл целиком командой `cat`.
- **Ты умеешь** брать начало (`head -n`) и конец (`tail -n`) файла.
- **Ты знаешь**, что для логов главный инструмент — `tail`.
- **Ты умеешь** считать строки, слова и байты через `wc -l`, `wc -w`, `wc -c`.
- **Ты знаешь**, что для больших файлов есть постраничный `less`.

## Домашка

1. На своей машине найди любой текстовый файл (например, лог или свои заметки) и посмотри его тремя способами: `cat`, `head -n 5`, `tail -n 5`. Почувствуй разницу.
2. Посчитай строки в этом файле через `wc -l`. Если файл большой, открой его через `less` и попробуй поиск: нажми `/`, введи слово, Enter (выход — `q`).
3. Склей два своих небольших файла командой `cat file1 file2` и посмотри, как текст идёт один за другим.

<details><summary>🤓 Для любопытных</summary>

**Почему `less` называется так странно.** Изначально была программа `more` — «показать больше» (она листала файл вперёд). Её улучшили в `less` — по принципу «less is more» (меньше значит больше). Ирония закрепилась в названии: `less` умеет больше, чем `more`, включая листание назад.

**`cat` — не только просмотр.** Настоящая сила `cat` в склейке файлов: `cat part1 part2 part3 > whole` соберёт из кусков один файл. А `cat file | grep ...` отдаст содержимое дальше по конвейеру — это мы разберём в уроке про пайпы.

**`head` и `tail` работают не только по строкам.** Ключ `-c` задаёт количество байт: `head -c 100 file` покажет первые 100 байт. А `tail -n +5` покажет файл, начиная с пятой строки и до конца — приём, который спасает, когда нужно «всё, кроме первых строк».

**`tail -f` и живые серверы.** Во флаге `-f` живёт вся суть мониторинга: команда не завершается, а ждёт новых строк. Администраторы держат такое окно открытым весь день. Есть и вариант `-F`, который переживает «ротацию логов» — когда система переименовывает и пересоздаёт файл лога.

</details>
