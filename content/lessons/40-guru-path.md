## Зачем это тебе

Курс заканчивается — путь нет. Ты освоил базу, с которой можно жить: файлы, права, процессы, сеть, службы, бэкапы. Дальше важно не потерять навык и не распылиться. В этом уроке — карта: что ты уже умеешь, какие темы открываются следом и где брать хорошую документацию, когда что-то забыл.

## Как это работает

### Что ты уже умеешь

| Модуль | Навык |
| --- | --- |
| 1. Знакомство | Что такое Linux, терминал, анатомия команды |
| 2. Файлы | Создавать, читать, искать и соединять команды пайпами |
| 3. Права | Пользователи, rwx, chmod/chown, sudo |
| 4. Процессы | ps/top, сигналы, kill, свободные ресурсы |
| 5. Оболочка | Переменные, скрипты, fish/zsh, оформление |
| 6. Сеть | IP/DNS/порты, ping/curl, SSH, scp/rsync |

| 8. Гуру | Производительность, архивы/бэкапы, безопасность, финальный проект |

Теперь ты умеешь то, что нужно 90% повседневной работы с Linux. Не «знаешь все флаги» — а можешь зайти на незнакомую машину и разобраться. Это другой, гораздо более ценный навык.

### Куда двигаться дальше

Выбери одну дорогу, а не пять сразу:

- **Администрирование.** Глубже systemd, диски и LVM, сети, работа с пользователями. Логичное продолжение этого курса.
- **Контейнеры.** `docker` и `podman`: упаковать приложение со всеми зависимостями и запускать где угодно. Сейчас это требование почти в каждой вакансии.
- **Автоматизация.** Ansible, bash-скрипты, CI/CD. Когда серверов больше одного — руками уже не получится.
- **Мониторинг.** Prometheus, Grafana, алерты. Чтобы узнавать о проблеме раньше, чем пользователи.
- **Безопасность.** Hardening, аудит, разбор инцидентов — из урока 38 вглубь.

Универсальный совет: возьми одну маленькую задачу и доведи её до конца. «Поставить и настроить домашний сервер», «завернуть свой проект в docker», «написать скрипт, который делает бэкап и присылает уведомление». Проекты учат быстрее курсов.

### Где брать документацию

- `man <команда>` — всегда под рукой; `tldr <команда>` — короткие примеры.
- `explainshell.com` — разбирает любую команду по частям.
- **Arch Wiki** — лучшая документация по Linux вообще, полезна с любым дистрибутивом.
- **The Linux Command Line** (Уильям Шоттс, бесплатно) — если хочешь системно пройтись по базе.
- **Brendan Gregg «Linux Performance»** — всё о производительности и eBPF (урок 36).
- **OverTheWire: Bandit** — игра-практикум по терминалу, отлично закрепляет навык.
- **crontab.guru** и **ShellCheck** — когда пишешь cron или скрипт.

### Совет без пафоса: храни конфиг в git

Ты настроил `.bashrc`, `.gitconfig`, конфиг SSH, редактор. Однажды купишь новый ноутбук или переустановишь систему — и всё это придётся вспоминать заново. Есть простое решение: завести репозиторий со своими конфигами («dotfiles»).

```bash
mkdir -p ~/dotfiles
mv ~/.bashrc ~/dotfiles/bashrc      # файлы переезжают в репозиторий
ln -s ~/dotfiles/bashrc ~/.bashrc   # а на старом месте — ссылка
cd ~/dotfiles && git init && git add . && git commit -m "мои конфиги"
```

Что это даёт, кроме красоты: историю правок (видно, что и когда ты сломал), возможность откатиться, перенос настроек на новую машину одной командой и эксперименты в ветках. Никакой магии и никакого «гуру-пафоса»: это просто гит для твоих текстовых настроек.

## Домашка

Чтобы навык не остыл:

1. Заведи репозиторий с конфигами: `mkdir ~/dotfiles`, перенеси туда `.bashrc` (или `config.fish`) и `.gitconfig`, поставь симлинки, сделай `git init` и первый коммит.
2. Выбери одну дорогу из урока и одно маленькое дело на выходных: подними домашний сервер, поставь Docker, напиши скрипт-бэкап с уведомлением.
3. Поставь `tldr`: `sudo apt install tldr` (или `dnf install tldr`, `pacman -S tldr`) — и пользуйся им вместо гугла.
4. Пройди первые 10 уровней OverTheWire: Bandit — это закрепит уверенность в терминале.
5. Перечитай свой конспект по урокам: отметь три темы, которые были самыми трудными, и вернись к ним.

## <details><summary>🤓 Для любопытных</summary>

- **dotfiles удобнее через менеджер**: `chezmoi` или GNU Stow управляют симлинками и различиями между машинами (`stow -t ~ bash git`).
- Следующий технический уровень: LVM и RAID, снапшоты btrfs/ZFS, ядро и sysctl, cgroups, контейнеры изнутри (namespaces).
- Для контейнеров начни с `podman` (rootless, предпочтителен) и только потом переходи к оркестрации.
- Мониторинг: `node_exporter` + Prometheus + Grafana; для домашнего сервера хватит Netdata или Uptime Kuma.
- Сертификации для ориентира: LPIC-1, RHCSA, CKA (Kubernetes). Полезны как карта тем, даже если ты не собираешься сдавать.
- Профессиональная привычка: любой ответ начинать не с «мысли», а с фактов — `df -h`, `free -h`, логи. Это отличает админа от гадателя.
</details>
