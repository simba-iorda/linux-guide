## Зачем это тебе

В Проводнике ты создаёшь папки правой кнопкой, копируешь мышкой и перетаскиваешь файлы. В терминале то же самое делается командами — и, честно говоря, быстрее: одну команду можно повторить, вставить в скрипт или применить сразу к десятку файлов.

Четыре глагола закрывают почти всю повседневную работу с файлами: **создать**, **скопировать**, **переместить**, **переименовать**. Разберём их по одному, вместе с типичными ошибками новичков.

## Как это работает

### Создать: touch и mkdir

```bash
touch notes.txt        # создать пустой файл
touch a.txt b.txt      # создать сразу два файла
mkdir backup           # создать папку
mkdir -p a/b/c         # создать всю цепочку папок разом
```

`touch` переводится «коснуться». Если файла нет — он создаётся пустым. Если файл уже есть — `touch` ничего не портит, только обновляет дату последнего изменения.

`mkdir` — **m**a**k**e **dir**ectory, «создать директорию». Флаг `-p` значит **parents**, «родители»: он создаёт все промежуточные папки по пути.

Что будет **без** `-p`? Если написать `mkdir a/b/c`, а папки `a` ещё нет, команда ответит `mkdir: cannot create directory 'a/b/c': No such file or directory` и ничего не сделает. С флагом `-p` она молча построит `a`, потом `b`, потом `c`. Это самая частая ошибка новичка при создании структуры проекта.

### Скопировать: cp

```bash
cp notes.txt notes_copy.txt    # копия файла под новым именем
cp notes.txt backup/           # копия в папку (имя сохранится)
cp -r docs docs_copy           # копировать папку целиком
```

`cp` — **c**o**p**y. Первый аргумент — что копируем (**источник**), последний — куда (**назначение**). Оригинал остаётся на месте.

Флаг `-r` — **recursive**, «рекурсивно»: копировать папку со всем содержимым. Без него `cp docs docs_copy` откажется работать: `cp: -r not specified; omitting directory 'docs'`. Это задумано — чтобы ты случайно не скопировал гигабайты.

Если назначение — существующая папка (`cp notes.txt backup/`), файл копируется внутрь неё под тем же именем. Если назначение — имя, которого нет, `cp` создаст файл с этим именем.

### Переместить и переименовать: mv

В Linux переименование и перемещение — **одна и та же операция**. Файл просто меняет своё имя, а имя может включать путь.

```bash
mv old.txt new.txt      # переименовать (тот же путь, новое имя)
mv notes.txt backup/    # переместить в папку
mv notes.txt /tmp/      # переместить по абсолютному пути
```

`mv` — **m**o**v**e. Оригинал исчезает: либо под новым именем, либо в новой папке. Если в назначении уже есть файл с таким именем, `mv` перезапишет его без предупреждения — поэтому переименовывай внимательно.

Разница `cp` и `mv` в одной фразе: `cp` делает **копию** (теперь файлов два), `mv` **переносит** (файл один, просто в другом месте).

### Проверить себя: ls

После любой операции полезно посмотреть, что получилось:

```bash
ls -l      # подробности: размер, дата
ls -la     # ещё и скрытые файлы
```

Иногда файл создан, а его не видно — потому что имя начинается с точки и `ls` его прячет. Тогда нужен `-a`.

> 💡 Маски (glob). Оболочка сама раскрывает `*` до списка файлов: `cp *.txt backup/` скопирует все `.txt` разом. Но именно поэтому команда может задеть больше, чем ты ждал. Перед операцией с маской набери `ls *.txt` и посмотри, что попадёт под неё.

## Итог дня

- **Ты умеешь** создавать пустые файлы (`touch`) и папки (`mkdir`, `mkdir -p`).
- **Ты умеешь** копировать файлы (`cp`) и папки (`cp -r`).
- **Ты понимаешь**, что переименование и перемещение — это одна команда `mv`.
- **Ты знаешь**, что без `-p` вложенные папки не создать, а без `-r` папку не скопировать.
- **Ты проверяешь** результат операций через `ls -l`.

<details><summary>🤓 Для любопытных</summary>

**Почему переименование и перемещение — одно и то же.** Имя файла — это запись в каталоге, которая ссылается на inode (структуру с метаданными и адресами данных). `mv` просто удаляет запись из одного каталога и создаёт в другом, а данные на диске не двигаются. Поэтому `mv` внутри одного раздела мгновенен, даже для файла в несколько гигабайт. Если же перемещать между разными дисками, системе придётся реально скопировать данные и удалить оригинал — это уже долго.

**`cp -a` против `cp -r`.** Флаг `-r` копирует только содержимое, а `-a` («archive») сохраняет ещё и права, владельца, даты. Для бэкапов системы правильнее `-a`, для обычных задач хватает `-r`.

**Опасность `mv` при перезаписи.** `mv a.txt b.txt` молча затрёт существующий `b.txt` — корзины и подтверждения нет. Флаг `-n` («no clobber») запрещает перезапись: `mv -n a.txt b.txt` просто откажется, если `b.txt` уже есть.

**Ссылки вместо копий.** Если нужно, чтобы на один файл было два имени без дублирования данных, используют `ln` (жёсткая ссылка) или `ln -s` (символическая). Это тема модуля про права; пока достаточно знать, что такие команды существуют.

</details>
