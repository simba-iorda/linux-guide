## Зачем это тебе

Пройти урок про права и не научиться пользоваться `sudo` — значит застрять на первом же шаге: поставить программу, поправить системный конфиг, отредактировать чужой файл — всё это требует root. Но и жить под root нельзя: любая опечатка в такой сессии может оставить тебя без системы.

`sudo` — это компромисс, который придумали именно для этого: **взять власть на одну команду и сразу вернуть**. Разберёмся, как он работает и что писать, если он ругается.

## Как это работает

`sudo` = *superuser do*, «сделай это как суперпользователь». Ты ставишь его перед командой:

```bash
sudo dnf install nano      # поставить программу (Fedora)
sudo apt install nano      # то же в Ubuntu/Debian
sudo systemctl restart ssh # перезапустить службу
sudo whoami                # выведет root — проверить легко
```

Что важно знать:

- **Пароль спрашивают твой, не root.** Так система понимает, что за клавиатурой действительно ты. Root-пароля часто вообще нет — вход под root закрыт.
- **Пароль помнится несколько минут.** Не нужно вводить его на каждую команду подряд.
- **Проверяется список разрешённых.** Право на sudo есть не у всех: пользователей добавляют в группу `sudo` (Debian/Ubuntu) или `wheel` (Fedora, Arch, открытый openSUSE).
- **Каждый запуск пишется в лог.** Всё, что делалось через sudo, можно найти в системном журнале — это и защита, и способ разобраться «кто это поправил».

Сравни с `su`: `su - alice` **полностью переключает** тебя в другого пользователя (нужен его пароль). `sudo` же не переключает контекст, а только повышает права для одной команды. Поэтому `sudo` — способ по умолчанию, а `su -` — инструмент для случаев, когда нужно именно «зайти как другой».

Типичные варианты использования:

```bash
sudo -i                 # открыть root-сессию (для длинной работы, потом exit)
sudo -u www-data ls /  # выполнить команду от другого пользователя
sudo -l                 # показать, что лично тебе разрешено
sudo visudo             # безопасно редактировать файл /etc/sudoers
```

**Как читать ошибки sudo:**

- `user is not in the sudoers file. This incident will be reported.` — твоего аккаунта нет в списке. Не паникуй: «reported» — это просто запись в лог. Решение: попросить администратора добавить тебя в группу, например `sudo usermod -aG wheel user`.
- `Sorry, try again.` — неверный пароль, набран неправильно (например, раскладка).
- `sudo: команда: command not found` — на самом деле команды нет в системе: sudo её не нашёл, а не «запретил».
- `sudo: a terminal is required to read the password` — ты запускаешь sudo в скрипте или без терминала; пароль спросить не у кого.

## Итог дня

Сейчас ты умеешь:

- разово выполнять команду от root через `sudo` и проверять результат командой `sudo whoami`;
- объяснять, почему sudo безопаснее постоянной root-сессии и где искать журнал сделанного;
- выполнять команды от другого пользователя (`sudo -u`) и смотреть свои полномочия (`sudo -l`);
- узнавать ошибки sudo и понимать текст сообщения о sudoers;
- называть группу с правами sudo в своём дистрибутиве (`sudo` или `wheel`).

## Домашка

Всё на твоей машине. Сначала разведка, потом пара безопасных действий.

1. Убедись, кто ты: `whoami` → обычное имя. Затем `sudo whoami` → `root`. Разница на одну команду — это и есть суть sudo.
2. Посмотри, что тебе разрешено: `sudo -l`. В конце будет список правил — примерно `(ALL : ALL) ALL`.
3. Проверь свои группы: `groups`. Должна быть `sudo` (Ubuntu/Debian) или `wheel` (Fedora/Arch).
4. Войди в root-сессию и выйди: `sudo -i`, потом `exit`. Обрати внимание, как меняется приглашение командной строки.
5. Выполни что-нибудь безвредное от root: `sudo ls -l /root`. Ты увидишь содержимое домашней папки root, куда обычным пользователям хода нет.
6. Проверь границу прав: `sudo chown root /etc/hosts` — сработает, а без sudo — `Operation not permitted`.
7. Загляни в логи: `sudo journalctl -u sudo -n 20` или `sudo tail /var/log/auth.log`. Ты увидишь свои же записи о запуске sudo.

## <details><summary>🤓 Для любопытных</summary>

Файл правил — `/etc/sudoers`, и редактируют его **только** через `sudo visudo`: утилита проверяет синтаксис перед сохранением. Опечатка в sudoers без проверки легко запирает тебя без прав на sudo.

Формат правила: кто, где, от чьего имени, что именно. Пример: `%devs ALL=(ALL) /usr/bin/systemctl restart nginx`. Так группа `devs` может перезапускать только nginx и ничего больше — принцип наименьших привилегий в действии.

Полезные опции в sudoers: `NOPASSWD` (без пароля — удобно для служебных задач), `Defaults timestamp_timeout=5` (пароль помнится 5 минут вместо 15), `Defaults use_pty` (команды выполняются в отдельном псевдотерминале — защита от трюков с подменой tty).

Современные системы всё чаще используют **wheel с плагином** или `polkit` для графики: тогда действия вроде «подключить диск» спрашивают пароль без прямого sudo. В Fedora/Arch в качестве упрощённой альтернативы появляется `run0`, а на BSD-подобных системах популярен `doas` — маленький sudo с коротким конфигом.

Как это вообще устроено технически: бит SUID сделал бы из программы вечного root, а sudo проверяет правила, потом через системные вызовы меняет владельца процесса — и записывает событие в журнал.
