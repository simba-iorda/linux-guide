## Зачем это тебе

«Где-то у меня был этот конфиг...», «в каком файле я записал пароль от вайфая?», «в каком из логов эта ошибка?» — поиск нужен постоянно. В графике ты блуждаешь по папкам наугад. В терминале есть две команды, которые решают две разные задачи поиска:

- **найти файл** по имени — `find`;
- **найти текст** внутри файлов — `grep`.

Не путай их: `find` ищет по файловой системе, `grep` — по содержимому.

## Как это работает

### Поиск файлов: find

`find` идёт по дереву каталогов и проверяет каждый файл по условию. Ему надо указать, **где искать** и **что искать**:

```bash
find . -name "*.log"        # все файлы, оканчивающиеся на .log, начиная от текущей папки
find . -iname "readme*"     # то же, но без учёта регистра (-i — ignore case)
find . -type d -name docs   # только папки (-type d) с именем docs
find /var -type f -size +100M   # файлы больше 100 МБ в /var
```

Разберём по частям:

- `.` — где искать: точка значит «от текущей папки и вглубь». Можно указать `/home/user` и т.п.
- `-name` — искать по имени файла. Шаблон в кавычках.
- `-iname` — то же, но игнорируя регистр: `README`, `readme` и `ReadMe` найдутся все.
- `-type f` — только файлы, `-type d` — только папки.
- `-size +100M` — больше 100 мегабайт (`+` — больше, `-` — меньше).

`find` **точный, но медленный**: он реально обходит диск, а не заглядывает в заранее собранный список. Зато находит всегда — даже то, что создали секунду назад.

Что будет, если забыть `-name`? `find .` без условий просто выведет **все** файлы и папки от текущей и вглубь. Иногда это тоже нужно, но чаще — целое море строк.

> 💡 В нашем тренажёре команды `find` нет (это тяжёлая команда, ищет реально по диску). Мы разбираем её в тексте, а потренируемся на ней в домашке — на своём компьютере. В песочнице будем искать текст командой `grep`.

### Поиск текста: grep

`grep` ищет строки, в которых встречается нужный кусок текста:

```bash
grep "ошибка" app.log       # строки, где есть слово «ошибка»
grep -i "error" app.log     # то же, но без учёта регистра: ERROR, Error, error
grep -n "error" app.log     # с номерами строк — удобно прыгать в редакторе
grep -v "debug" app.log     # наоборот: все строки, где debug НЕ встречается
grep -c "error" app.log     # сколько строк нашлось
```

Что делает каждая буква:

| Флаг | Смысл | Что будет без него |
|---|---|---|
| `-i` | ignore case — регистр не важен | `error` и `Error` считаются разными |
| `-n` | добавить номера строк | номеров не видно, только текст |
| `-v` | invert — показать всё, кроме совпадений | показываются только совпадения |
| `-c` | count — только количество строк | выводятся сами строки |

`grep` можно дать сразу несколько файлов: `grep -n "error" app.log second.log` — он напишет, из какого файла какая строка.

### Читаем ошибки

- `grep: app.log: No such file or directory` — команда есть, а файла с таким именем в текущей папке нет. Проверь: `ls`.
- `grep: missing pattern` — ты не указал, что искать. Первым аргументом должен идти шаблон.
- Если `grep` **ничего не вывел и сразу вернул промпт** — это не ошибка. Просто совпадений нет.

### Найти файл или найти текст — что когда

| Задача | Инструмент |
|---|---|
| Не помню, где лежит файл по имени | `find . -name "имя"` |
| Ищу слово внутри файла (или нескольких) | `grep "слово" файл` |
| Нужны номера строк с совпадением | `grep -n` |
| Нужно всё, кроме этого слова | `grep -v` |

## Итог дня

- **Ты понимаешь** разницу: `find` ищет файлы по имени, `grep` — текст внутри файлов.
- **Ты умеешь** искать строки командой `grep` и не пугаться пустого вывода.
- **Ты знаешь** флаги `grep`: `-i` (регистр), `-n` (номера строк), `-v` (наоборот), `-c` (только число).
- **Ты знаешь**, как устроен `find . -name "шаблон"` и когда он нужен.
- **Ты читаешь** ошибку `No such file or directory` и знаешь, что проверить через `ls`.

## Домашка

1. На своём компьютере найди все текстовые файлы с расширением `.txt` в домашней папке: `find ~ -name "*.txt"`. Если вывод слишком большой, добавь `-type f`.
2. Найди файл, чьё имя ты точно помнишь, но не помнишь расположения — например `find ~ -iname "*notes*"`.
3. Возьми любой лог или текстовый файл и потренируй `grep`: найди в нём слово, посчитай строки с ним через `grep -c`, посмотри их с номерами через `grep -n`.

<details><summary>🤓 Для любопытных</summary>

**Почему grep так называется.** Название — от команды в редакторе `ed`: `g/re/p` — «global / regular expression / print», то есть «найти по всему файлу по шаблону и напечатать». Сокращение прижилось и стало отдельной программой.

**grep и регулярные выражения.** Слово в шаблоне — это уже простейшая регулярка. Можно делать сложнее: `grep -E "err|warn"` найдёт ошибки **или** предупреждения (вертикальная черта = «или»), `grep "^Error"` — только строки, начинающиеся со слова Error.

**Работа с папками.** У `grep` есть флаг `-r` (recursive): `grep -rn "TODO" .` ищет текст во всех файлах папки и глубже, с номерами строк. Это то, что нужно разработчику по сто раз на дню. В тренажёре `-r` есть не везде, но в настоящем терминале — обязательно попробуй.

**find умеет не только искать.** У него есть действие `-delete` (найденное — удалить) и `-exec` (выполнить команду для каждого найденного файла). Мощно и опасно одновременно; мы дойдём до этого смысла в лабораториях.

**Один устаревший, но быстрый родственник.** `locate` ищет не по диску, а по заранее построенной базе путей — мгновенно, но база обновляется отдельной командой (`updatedb`) и успевает устареть. `find` медленнее, зато всегда актуален.

</details>
