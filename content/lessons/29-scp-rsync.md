## Зачем это тебе

Ты уже умеешь заходить на сервер по SSH. Следующий вопрос — а как закинуть туда проект, забрать логи или держать резервную копию в актуальном состоянии? Для этого есть два инструмента: `scp` (простое копирование) и `rsync` (умная синхронизация, которая передаёт только изменения). Разница между ними экономит часы, когда файлов гигабайты.

## Как это работает

### scp — просто скопировать

`scp` работает как `cp`, только между машинами — по тому же SSH-туннелю. Один аргумент с `host:` — источник или приёмник.

```bash
scp file.txt user@host:/tmp/        # отправить файл на сервер
scp user@host:/var/log/app.log .    # забрать файл с сервера
scp -r dir/ user@host:~/            # скопировать папку целиком (-r = recursive)
```

Просто и предсказуемо. Но `scp` копирует **всё целиком каждый раз**: изменилась одна строка в файле на 1 ГБ — поедет весь гигабайт.

### rsync — передать только изменения

`rsync` сначала сравнивает источник и приёмник и передаёт **только различия**. Поэтому повторная синхронизация большой папки почти мгновенная.

```bash
rsync -avz dir/ user@host:~/dir/    # архивный режим, сжатие, по SSH
rsync -avzP big.iso user@host:~     # с прогрессом и докачкой
rsync -avz --dry-run src/ dst/      # 🔵 показать, что будет сделано, ничего не меняя
```

Разберём ключи: `a` — archive (сохранить права и время), `v` — показать файлы, `z` — сжать при передаче, `P` — прогресс и докачка, `--dry-run` — репетиция.

| | scp | rsync |
| --- | --- | --- |
| Что передаёт | Всё целиком | Только изменения |
| Повторная синхронизация | Снова всё | Почти мгновенно |
| Докачка и прогресс | Нет | `-P` |
| Удалять лишнее в приёмнике | Нет | `--delete` 🔴 |
| Сложность | Минимальная | Чуть выше |

### Слеш в конце — важная мелочь

```bash
rsync -avz dir/ user@host:~/dir/    # содержимое папки dir/
rsync -avz dir  user@host:~/dir/    # сама папка dir внутри dir/
```

Без слеша rsync положит папку внутрь приёмника; со слешем — скопирует её содержимое. Запомни: **слеш в конце = «внутренности»**.

> 🔴 `rsync --delete` стирает в приёмнике всё, чего нет в источнике. Ошибся путём — потерял данные. Всегда сначала прогоняй с `--dry-run` и смотри список, что удалится.

- Ты знаешь, что `rsync` передаёт только изменения и умеешь читать ключи `-avz`, `-P`, `--dry-run`.

## Домашка

На своей машине (можно без сервера — rsync умеет и локально):

1. Локальная репетиция: `rsync -avz --dry-run ~/Documents/ /tmp/docs-backup/` — посмотри, что предлагается скопировать.
2. Убери `--dry-run` — папка скопируется. Запусти второй раз: теперь передаётся почти ничего.
3. `touch ~/Documents/test.txt` и снова `rsync -avz ~/Documents/ /tmp/docs-backup/` — поедет только этот файл.
4. Если есть VPS: `rsync -avzP ~/project/ user@сервер:~/project/` — с прогрессом. Оборви и запусти снова: докачает.
5. `scp -r ~/project user@сервер:~/` — почувствуй разницу: scp копирует целиком, каждый раз.

## <details><summary>🤓 Для любопытных</summary>

- `rsync --checksum` сравнивает файлы по контрольной сумме, а не по времени и размеру — точнее, но медленнее.
- `--exclude='*.log' --exclude='node_modules/'` — исключения из синхронизации; `--include` задаёт приоритеты.
- rsync-алгоритм передаёт не файл целиком, а **дельту** по блокам: даже при изменении середины файла едут только изменённые куски.
- Переезд сервера: два `rsync`, потом окно простоя, третья догоняющая синхронизация — данные почти без остановки сервиса.
- `tar -czf - dir/ | ssh user@host 'tar -xzf - -C /opt'` — передача архива потоком, без промежуточного файла. Для регулярной синхронизации всё равно лучше rsync.
- `rclone` — то же самое, но для облаков (Google Drive, S3 объявлены как «диск»).
</details>
