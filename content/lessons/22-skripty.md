## Зачем это тебе

Каждый день ты делаешь одно и то же руками: заходишь в папку проекта, обновляешь пакеты, делаешь бэкап, отправляешь файл. Пять минут, двадцать раз в месяц — это уже часы.

**Скрипт** — это обычный текстовый файл, в котором записаны команды. Ты запускаешь одну строку вместо десяти. Никакой магии: то же, что ты вводишь в терминал, только сохранённое. Именно с этого начинается автоматизация, и первый скрипт ты напишешь уже сегодня.

## Как это работает

### Из чего состоит скрипт

```bash
#!/usr/bin/env bash
# Резервная копия папки проекта

NAME="${1:-world}"
echo "Привет, $NAME!"
```

Разберём построчно:

- **`#!/usr/bin/env bash`** — первая строка называется **shebang** («шебанг», от sharp + bang). Она говорит системе, чем запускать этот файл: «найди программу bash и передай ей меня». Без неё файл тоже может сработать, если запустить его как `bash script.sh`, но при запуске `./script.sh` система не поймёт, что это за файл.
- **`# ...`** — комментарий. Ядро и оболочка его игнорируют, он для людей. Пиши комментарии: через месяц ты не вспомнишь, зачем была эта строка.
- **`NAME="${1:-world}"`** — берём первый аргумент, переданный скрипту. Если аргумента нет, подставляем `world`. Фигурные скобки и кавычки — чтобы значение не «развалилось» при пробелах.
- **`echo "Привет, $NAME!"`** — печатаем строку, подставив значение переменной.

### Аргументы: как скрипт получает данные

| Запись | Что это |
|---|---|
| `$0` | имя самого скрипта |
| `$1`, `$2` | первый и второй аргументы |
| `$#` | сколько аргументов передали |
| `$@` | все аргументы списком |
| `$?` | код выхода последней команды (0 — успех) |

Пример: `./greet.sh Linux` — внутри `$1` будет `Linux`. Без фигурных скобок `$10` читается как `$1` и `0` подряд, поэтому в скриптах принято писать `"${10}"`.

### Как запустить

```bash
chmod +x backup.sh     # выдаём право на запуск — один раз
./backup.sh            # запускаем
```

Почему `./backup.sh`, а не просто `backup.sh`? Потому что оболочка ищет команды в папках из `PATH`, а текущая папка туда не входит — это защита от подмены системных команд файлом рядом с тобой. Точка в `./` означает «эта папка».

Если право на запуск не выдано, ты получишь `bash: ./backup.sh: Permission denied` — иди делай `chmod +x`. Есть и второй путь: `bash backup.sh` — запуск через оболочку, тогда право `x` не нужно вовсе.

### Полезная приправа

```bash
set -euo pipefail   # строгий режим: падать на ошибке, на пустой переменной и в пайпах
bash -x backup.sh   # отладка: печатает каждую выполняемую строку
```

Условия и циклы выглядят знакомо, если ты хоть раз видел программирование:

```bash
if [[ -f config.yaml ]]; then
    echo "конфиг на месте"
else
    echo "конфиг потерялся"
fi

for f in *.log; do
    echo "Обрабатываю $f"
done
```

**Как читать ошибки:**

- `bash: ./script.sh: Permission denied` — нет права на запуск: `chmod +x`.
- `bash: ./script.sh: /usr/bin/env^M: bad interpreter` — файл сохранён в Windows-кодировке строк (CRLF). Странный `^M` в конце имени и есть лишний символ возврата каретки. Лечится `sed -i 's/\r$//' script.sh` или пересохранением в LF.
- `bash: ./script.sh: line 3: синтаксическая ошибка` — незакрытая кавычка или забытый `fi`. Номер строки указан — иди туда.
- Скрипт молча ничего не делает — проверь, что переменные в кавычках (`"$file"`), и запусти с `bash -x`.

## Итог дня

Сейчас ты умеешь:

- объяснять, из чего состоит скрипт: shebang, комментарии, команды;
- создавать и дописывать файл скрипта (`>`, `>>`) и проверять содержимое;
- принимать аргументы через `$1`, `$#`, `$@` и давать значения по умолчанию (`${1:-default}`);
- выдавать право на запуск (`chmod +x`) и объяснять запуск `./script.sh` против `bash script.sh`;
- читать ошибки `Permission denied`, `bad interpreter` и синтаксические ошибки с номером строки.

## Домашка

Здесь ты наконец по-настоящему запускаешь скрипт. Папка: `~/scripts`.

1. Подготовь место: `mkdir -p ~/scripts && cd ~/scripts`.
2. Напиши скрипт: `nano greet.sh`, содержимое — shebang и две строки: `NAME="${1:-world}"` и `echo "Привет, $NAME!"`.
3. Попробуй запустить: `./greet.sh` → получишь `Permission denied`. Прочитай ошибку — это про право на запуск.
4. Выдай право и запусти: `chmod +x greet.sh && ./greet.sh` → `Привет, world!`.
5. Передай аргумент: `./greet.sh Linux` → `Привет, Linux!`. Проверь `$#`: добавь в скрипт строку `echo "Аргументов: $#"`.
6. Сравни способы запуска: `bash greet.sh Ubuntu` — работает и без права `x`. Убери право (`chmod 644 greet.sh`) и проверь оба способа снова.
7. Сделай второй скрипт `backup.sh`: создаёт папку `~/backup/$(date +%F)` и копирует туда файлы из `~/scripts`. Запусти его и проверь результат.
8. Отладь вслух: `bash -x backup.sh` — увидишь каждую выполняемую строку. Так ищут, где скрипт свернул не туда.
9. Сломай специально: удали первую строку shebang и запусти `./backup.sh` — теперь система не знает, чем запускать файл. Верни строку обратно.

## <details><summary>🤓 Для любопытных</summary>

**`set -euo pipefail`** — три правила одной строкой: `-e` падать при ошибке любой команды, `-u` ругаться на неопределённую переменную, `pipefail` считать пайп неудачным, если упала любая его часть (по умолчанию важен только последний). В серьёзных скриптах это первая строка после shebang.

**Циклы и условия** покрывают почти всё: `if [[ -f "$f" ]]`, `for f in *.log`, `while read -r line; do ... done < file`, `case "$1" in start) ... ;; esac`. Проверки в `[[ ]]`: `-f` файл существует, `-d` папка, `-x` исполняемый, `-z` строка пустая, `-eq` числа равны.

**Функции** избавляют от повторов: `backup() { tar -czf "$1.tgz" "$1"; }`, дальше вызываешь `backup docs`.

**`trap`** выполняет уборку при аварийном завершении: `trap 'rm -f "$TMPFILE"' EXIT` — временный файл не останется даже при `Ctrl+C`.

**Проверка качества:** `shellcheck script.sh` (пакет `shellcheck`) находит опечатки и опасные места: непроцитированные переменные, `rm -rf "$DIR/` без проверки на пустоту и прочее. Хорошая привычка — прогонять через неё все скрипты.

**Портируемость:** `#!/bin/sh` и только POSIX-конструкции работают везде, включая минимальные контейнеры и Alpine. `#!/usr/bin/env bash` надёжнее, чем `#!/bin/bash`: на BSD и в NixOS bash лежит не в `/bin`.

</details>
