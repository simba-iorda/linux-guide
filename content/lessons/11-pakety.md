Программы в Linux не ищут по сайтам и не скачивают «инсталляторы». Их берут из **репозиториев** — проверенных хранилищ, которые курирует сам дистрибутив.

## Как это устроено

**Пакет** — это архив с программой, её настройками и списком зависимостей. **Зависимости** — другие пакеты, без которых программа не заработает. **Пакетный менеджер** сам скачает программу вместе со всем, что ей нужно, проверит подпись и поставит.

Отсюда два больших плюса: ты не собираешь зависимости руками и получаешь обновления безопасности вместе с остальной системой.

## Какой командой

Каждый дистрибутив использует свой менеджер:

| Действие | Debian / Ubuntu | Fedora / RHEL |
|---|---|---|
| Обновить списки | `apt update` | `dnf check-update` |
| Установить | `apt install nano` | `dnf install nano` |
| Удалить | `apt remove nano` | `dnf remove nano` |
| Найти | `apt search editor` | `dnf search editor` |
| Показать информацию | `apt show nano` | `dnf info nano` |

Идея одинаковая везде: сначала обнови информацию о доступных пакетах, потом ставь или удаляй.

## Посмотреть справку

Если забыл точное слово, у пакетного менеджера есть встроенная инструкция:

```bash
man apt
```

## Правило хорошего тона

Ставь программы только из репозиториев дистрибутива. Скачанные со сторонних сайтов скрипты вроде `install.sh` не получают автоматических обновлений и могут содержать что угодно — запускать их стоит только от проверенных авторов и с пониманием, что внутри.

> 💡 `apt` — не единственный способ для всех систем: в Fedora это `dnf`, в Arch — `pacman`, в openSUSE — `zypper`. Логика одна, буквы разные.
