## Зачем это тебе

Бывает ситуация: fish нравится, но пугает его несовместимость с bash — половина рецептов из интернета написана для bash, и переписывать их не хочется. Или наоборот: хочется удобства fish, но с полной совместимостью.

Ответ на оба желания — **zsh**. Это оболочка, которая «понимает bash, но умеет больше»: умное автодополнение, расширенные маски файлов, плагины. А **oh-my-zsh** — набор готовых настроек, тем и плагинов, чтобы не собирать всё руками по кусочкам.

## Как это работает

### zsh: та же логика, больше возможностей

Синтаксис zsh почти полностью совпадает с bash: `VAR=value`, `export`, `$1`, пайпы, редиректы, `.bashrc`-подобные скрипты — всё работает. Именно поэтому zsh часто ставят «поверх» привычек: команды не надо переучивать.

Что он добавляет:

- **Умное автодополнение.** `Tab` показывает варианты для команд, ключей и путей, по ним можно ходить стрелками. Команда `ls` подсвечивается, если она существует (это уже модуль `zsh-syntax-highlighting`).
- **Расширенные маски файлов.** `ls **/*.txt` находит файлы в любой глубине (в bash для этого раньше нужно было включать отдельную опцию).
- **Плагины и темы** как обычные подключаемые модули — вот тут и приходит oh-my-zsh.

### oh-my-zsh: набор настроек и плагинов

oh-my-zsh — это не отдельная оболочка, а **фреймворк настроек** для zsh. Он даёт:

- десятки **тем** для приглашения командной строки (`ZSH_THEME`);
- больше сотни **плагинов**: автодополнение git, подсветка синтаксиса, быстрая навигация (`z`, `extract`, `sudo` и т.д.);
- разумные настройки по умолчанию, чтобы не писать конфиг с нуля.

Конфигурация — один файл **`~/.zshrc`**. Минимум там такой:

```bash
export ZSH="$HOME/.oh-my-zsh"
ZSH_THEME="robbyrussell"
plugins=(git z sudo)
source $ZSH/oh-my-zsh.sh
```

Плагины указываются просто именами в скобках. Из коробки пригождаются: `git` (сокращения для гит-команд), `z` (прыжок в часто посещаемые папки), `sudo` (двойной `Esc` добавит `sudo` к текущей команде), `extract` (распаковка любого архива командой `x`).

Темы задаёт строка `ZSH_THEME`. Самые популярные — `robbyrussell` (простая и быстрая), `agnoster` (стрелочки, требует шрифт с глифами), `powerlevel10k` (отдельный проект, настраивается интерактивным мастером). Поскольку шрифты с глифами — отдельная история, в уроке 25 мы разберём её отдельно.

### Установка и переключение

Ниже установщик oh-my-zsh скачивается через `curl` — утилиту, которая тянет данные по ссылке (подробно о ней — в модуле про сеть).

```bash
# 1) сама оболочка
sudo apt install zsh      # Ubuntu/Debian
sudo dnf install zsh      # Fedora
sudo pacman -S zsh        # Arch

# 2) oh-my-zsh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"

# 3) сделать оболочкой по умолчанию
chsh -s $(which zsh)
```

Проверить, что стало: `echo $SHELL` должен показать путь к zsh. Приглашение zsh в песочнице выглядит как `~/ ❯` — так его легко отличить от bash (`user@linux:~$`) и fish (`user@linux ~>`).

**Как читать ошибки:**

- `zsh: command not found: ll` — алиас не определён: он в `.bashrc`, а zsh читает `.zshrc`. Файлы не взаимозаменяемы.
- `compinit: insecure directories` — права на папки автодополнения слишком широкие: zsh предупреждает, что в них может кто-то дописать свой код. Лечится `compaudit` + `chmod go-w` по списку.
- Конфиг не применился после правки — нужен `source ~/.zshrc` или новый терминал.
- `oh-my-zsh: not found` после установки — модуль ищется по переменной `ZSH`, проверь, что она указывает на `~/.oh-my-zsh`.

## Итог дня

Сейчас ты умеешь:

- объяснять, чем zsh отличается от bash и почему его выбирают вместо fish;
- перечислять, что даёт oh-my-zsh: темы приглашения и плагины;
- править `~/.zshrc`: `ZSH_THEME`, `plugins=(...)`;
- ставить zsh и oh-my-zsh и делать zsh оболочкой по умолчанию через `chsh`;
- различать приглашения bash, fish и zsh и понимать, почему алиасы не «переезжают» между оболочками.

## Домашка

Установка и настройка — на твоей машине.

1. Установи zsh: `sudo apt install zsh` (Ubuntu/Debian), `sudo dnf install zsh` (Fedora), `sudo pacman -S zsh` (Arch).
2. Поставь oh-my-zsh: `sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"`. Скрипт сам предложит сделать zsh оболочкой по умолчанию.
3. Проверь приглашение: открой новый терминал — увидишь вид `➜  ~` (тема `robbyrussell`).
4. Смени тему: `nano ~/.zshrc`, поставь `ZSH_THEME="agnoster"` и выполни `source ~/.zshrc`. Обрати внимание на «квадратики» вместо стрелок — это шрифт без нужных глифов. Верни `robbyrussell` или займись шрифтами в уроке 25.
5. Добавь плагины: `plugins=(git z sudo extract)` и снова `source ~/.zshrc`. Проверь один: набери `gs` (плагин `git` понимает сокращение для `git status`) в папке с git-репозиторием.
6. Попробуй `z`: походи по разным папкам, потом набери `z sho` — zsh прыгнет в нужную по частоте использования.
7. Проверь умное дополнение: набери `cd /u` и нажми `Tab`, затем `ls -` и `Tab` — zsh покажет варианты ключей.
8. Вернись в bash, если он нужен как основной: измени оболочку обратно командой `chsh -s $(which bash)`.

## <details><summary>🤓 Для любопытных</summary>

zsh — оболочка с богатой историей: она появилась в 1990 году как «королевская оболочка» (Z = zsh) и собрала в себя идеи bash, ksh и tcsh. Долго была нишей энтузиастов, пока в 2019 году Apple не сделала её оболочкой по умолчанию в macOS — после этого популярность выросла резко.

Если не хочется тянуть весь oh-my-zsh, есть лёгкие менеджеры плагинов: `zinit`, `antigen`, `zplug`. Они грузят плагины лениво и заметно ускоряют запуск терминала. Своя тема — это функция `precmd`, которая собирает текст приглашения.

Для приглашения со «стрелочками» и подсветкой обычно ставят: `zsh-syntax-highlighting` (подсветка корректности), `zsh-autosuggestions` (серые подсказки из истории — как в fish!) и `powerlevel10k` (быстрая тема с гибкой настройкой). Ставятся как плагины или клонированием в `~/.oh-my-zsh/custom/plugins/`.

Про производительность: если новый терминал открывается медленно, помогает `zprof` — профилировщик zsh, покажет, какой плагин тормозит запуск (`zmodload zsh/zprof` и затем `zprof`).

Скрипты по-прежнему лучше писать на bash: она есть везде, а zsh может отсутствовать на сервере. В скриптах с shebang `#!/bin/zsh` используй zsh только если нужны его возможности (например, расширенные массивы и ассоциативные массивы).

</details>
