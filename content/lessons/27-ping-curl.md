## Зачем это тебе

«Интернет не работает» — и надо за минуту понять, где обрыв: у всей сети, у DNS или у конкретного сайта. Для этого у тебя будет два главных инструмента: `ping` проверяет «слышно ли собеседника», а `curl` показывает, что сервер реально отвечает. Ещё они пригодятся, чтобы скачать файл на сервер без браузера.

## Как это работает

### ping — «ау, ты тут?»

`ping` посылает маленький пакет **ICMP** и ждёт ответа. Если ответ пришёл — сеть до хоста рабочая.

```bash
ping 8.8.8.8          # по IP
ping google.com       # по имени (проверяет и DNS заодно)
```

Из вывода важны две вещи:

- **icmp_seq** — номер пакета: видно, все ли ответы дошли. Потеря пакетов («packet loss») — признак плохого канала.
- **time=12.3 ms** — задержка туда-обратно (**RTT**). До сервера в той же стране обычно 10–50 мс, до другого континента — 150–300 мс.

Без ключа `-c` ping работает «пока не надоест» и останавливается по `Ctrl+C`. В задачах выше симулятор сам показывает 4 пакета и статистику.

### curl — «покажи, что ты отдаёшь»

`curl` — это браузер без картинок: он стучится по URL и печатает ответ прямо в терминал.

```bash
curl https://example.com        # HTML страницы на экран
curl -I https://example.com     # только заголовки: код ответа, тип, размер
curl -O https://example.com/file.zip   # сохранить под исходным именем
curl -o data.zip URL            # сохранить под своим именем
```

`curl -I` — первое, что стоит делать при диагностике: в первой строке видно код ответа (`200 OK`, `301 Moved`, `404 Not Found`, `500`). Сервер жив и отвечает — значит, проблема дальше (в приложении, в базе). Не отвечает вовсе — смотри сеть.

### wget — «качалка с докачкой»

`wget` умеет то же, но заточен под скачивание файлов:

```bash
wget https://example.com/file.iso          # простой запрос
wget -c https://example.com/file.iso       # продолжить оборванную загрузку
wget -r -np https://example.com/docs/      # зеркало папки (осторожно, не на грузи чужие сайты)
```

Ключ `-c` (continue) — главная причина любить `wget`: большой файл можно докачать с того места, где оборвалось.

### Как читать ошибки

| Текст ошибки | Что означает |
| --- | --- |
| `Could not resolve host` | Не сработал DNS: имя не переводится в адрес |
| `Connection refused` | Порт закрыт или служба не запущена |
| `Connection timed out` | Пакеты не доходят: файрвол, роутер, сеть |
| `404 Not Found` | Сервер отвечает, но такого адреса у него нет |
| `301/302` | Переезд: страница переехала на другой URL |

Правило диагностики: **сначала ping по IP, потом ping по имени, потом curl**. Пингуется IP, но не имя → проблема в DNS. Не пингуется ни то, ни другое → сеть. Пингуется всё, а сайт не грузится → виноват конкретный сервис.

## Итог дня

- Ты умеешь проверять связь через `ping` и читать `icmp_seq`, потери пакетов и время ответа.
- Ты знаешь порядок диагностики: IP → имя → `curl`, и умеешь найти виновника (сеть или DNS).
- Ты умеешь забирать страницы и заголовки через `curl` и качать файлы с докачкой через `wget -c`.
- Ты различаешь по тексту ошибки `resolve`, `refused`, `timed out` и коды `404`/`500`.

## Домашка

На своей машине:

1. `ping -c 4 8.8.8.8` и `ping -c 4 google.com` — сравни время ответа и потери.
2. `curl -I https://example.com` — прочитай код ответа и сервер (заголовок `Server`).
3. `curl ifconfig.me` — так узнают свой внешний IP; сравни с адресом из `ip a` (там локальный).
4. Найди любой файл в интернете (образ ISO, архив) и скачай с докачкой: `wget -c <ссылка>`. Оборви `Ctrl+C` и запусти снова — увидишь, что качает дальше.

## <details><summary>🤓 Для любопытных</summary>

- **RTT** и **TTL**: TTL уменьшается на каждом маршрутизаторе — по нему `traceroute`/`mtr` строят путь до хоста.
- `ping -i 0.2` шлёт пакеты чаще, `ping -s 1200` — крупнее. Большие пакеты вскрывают проблемы с MTU (частая причина «сайт открывается, но не грузится»).
- `curl -v` печатает весь диалог: DNS → TCP → TLS → HTTP. `curl --resolve example.com:443:93.184.216.34` позволяет обратиться к серверу по IP, сохранив имя для HTTP-заголовка — приём при проверке «после смены DNS».
- `curl -X POST -H "Content-Type: application/json" -d '{"a":1}' URL` — так тестируют API из терминала. `curl -s URL | jq` — вытащить поля из JSON.
- «Безопасно ли качать через `curl URL | sudo bash`?» Нет. Скачай файл, посмотри его глазами, потом запускай.
</details>
