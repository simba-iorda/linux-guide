## Зачем это тебе

Ты вводишь `ls -la` по двадцать раз в день. Ты каждый раз пишешь `cd ~/projects/shop`, хотя можно было бы набрать три буквы. Ты запускаешь длинную команду обновления системы и копируешь её из заметок, потому что запомнить нереально.

Всё это лечится настройкой оболочки: **переменные** для значений, которыми пользуется система, и **алиасы** для коротких имён длинных команд. А чтобы настройки не пропадали после закрытия терминала, их кладут в файл `~/.bashrc`.

## Как это работает

### Переменные: коробка с наклейкой

Переменная — это имя, за которым хранится значение. Задаёшь так:

```bash
EDITOR=nano            # присвоили значение — без пробелов вокруг =
echo $EDITOR           # читаем: nano
```

Два правила, на которых спотыкаются все:

1. **Без пробелов вокруг `=`.** `EDITOR = nano` — не присваивание, а попытка запустить команду `EDITOR`, и оболочка ответит `command not found`.
2. **Чтобы прочитать значение, нужен `$`.** `echo EDITOR` напечатает слово «EDITOR», а `echo $EDITOR` — значение.

Оболочка уже завела для тебя кучу переменных: `HOME` (домашняя папка), `USER` (твой аккаунт), `PATH` (где искать команды), `SHELL` (какая оболочка запущена), `PWD` (текущая папка), `LANG` (язык). Посмотреть одну: `echo $HOME`. Все сразу: `env` или `printenv`.

**`export` — «передать детям».** Обычная переменная живёт только внутри текущей оболочки. `export VAR=value` делает её частью окружения: значение получат все программы, которые ты из неё запускаешь. Поэтому в конфигах переменные почти всегда пишут с `export`.

Самый важный пример — `PATH`:

```bash
$PATH                  # /usr/local/bin:/usr/bin:/bin — список папок через двоеточие
export PATH="$HOME/.local/bin:$PATH"   # добавить свою папку в начало поиска
```

Оболочка ищет команду в папках `PATH` слева направо. Поэтому твоя папка, добавленная в начало, перекрывает системные программы с тем же именем — и поэтому же текущая папка в `PATH` не входит: иначе любой файл рядом с тобой мог бы случайно «перекрыть» системную команду.

### Алиасы: короткое имя для команды

```bash
alias ll='ls -lah'      # теперь ll — это длинная команда
alias ..='cd ..'
alias update='sudo apt update && sudo apt upgrade -y'
```

Алиас — просто подстановка: оболочка, увидев `ll`, заменяет его на текст справа. Кавычки обязательны: без них пробелы разорвут присваивание. Посмотреть все алиасы: команда `alias`. Убрать: `unalias ll`.

### .bashrc: чтобы настройки жили долго

Всё, что ты вводишь руками, пропадёт при закрытии терминала. Постоянные настройки живут в файле **`~/.bashrc`** — «bash resource», который bash читает при каждом запуске интерактивного терминала.

Стандартный ритуал:

```bash
nano ~/.bashrc          # добавляем строки в конец файла
source ~/.bashrc        # применяем сейчас, не открывая новый терминал
```

`source` (то же самое — `.`) выполняет файл в текущей оболочке, а не в отдельном процессе. Именно поэтому изменения сразу действуют.

Разница между файлами конфигурации:

| Файл | Когда читается |
|---|---|
| `~/.bashrc` | каждый новый терминал: алиасы, вид приглашения |
| `~/.profile` / `~/.bash_profile` | при входе в систему: переменные окружения и PATH |
| `/etc/bash.bashrc`, `/etc/profile` | то же, но сразу для всех пользователей |

Есть и удобный нюанс: алиасы и функции из `.bashrc` доступны в интерактивном терминале, а в скриптах — нет (скрипты `.bashrc` не читают). Это правильно: скрипт не должен зависеть от твоих личных привычек.

**Как читать ошибки:**

- `bash: EDITOR: command not found` при попытке `EDITOR = nano` — та самая история с пробелами.
- Алиас не работает после правки `.bashrc` — забыл `source ~/.bashrc` или добавил строку в другой файл.
- `bash: /home/user/.bashrc: строка 12: синтаксическая ошибка` — в файл попал незакрытый кавычками текст. Ошибка называется строкой и номером, правь там.
- `alias: ll: not found` — попытка снять алиас, которого нет: ты создал его в другом терминале или не перечитал конфиг.

## Итог дня

Сейчас ты умеешь:

- задавать переменные (`VAR=value`) и читать их через `$VAR`, помня про запрет пробелов вокруг `=`;
- объяснять, что делает `export`, и куда добавлять свою папку в `PATH`;
- делать алиасы для частых команд и снимать их через `unalias`;
- дописывать настройки в `~/.bashrc` и применять их через `source`;
- отличать `.bashrc` от `.profile` и объяснять, почему скрипты их не читают.

## Домашка

Всё на своей машине. Работаем в твоём `~/.bashrc` — перед правкой сделай копию.

1. Копия на всякий случай: `cp ~/.bashrc ~/.bashrc.bak`.
2. Посмотри, что там уже есть: `cat ~/.bashrc | head -30` и `alias` (список активных алиасов).
3. Проверь переменные: `echo $HOME`, `echo $USER`, `echo $SHELL`, `echo $PATH`. Последняя — это список папок, где оболочка ищет команды.
4. Создай свою папку для своих программ: `mkdir -p ~/.local/bin` и добавь её в начало PATH — строкой `export PATH="$HOME/.local/bin:$PATH"` в конце `.bashrc`.
5. Применяй настройки: `source ~/.bashrc`, затем проверь `echo $PATH` — твоя папка должна быть первой.
6. Добавь алиасы: `alias ll='ls -lah'`, `alias ..='cd ..'`, `alias ports='ss -tulpn'`. Впиши их в `.bashrc`, снова `source ~/.bashrc` и проверь `ll` и `..`.
7. Почувствуй ошибку: выполни `EDITOR = nano` — увидишь `command not found`. Теперь ты знаешь, почему так.
8. Сделай проверку окружения: `env | head -15` — там же появится твой EDITOR, если ты его экспортировал.

## <details><summary>🤓 Для любопытных</summary>

Порядок, в котором bash читает файлы: при интерактивном входе — сначала `/etc/profile`, затем `~/.bash_profile` (или `~/.bash_login`, `~/.profile`), а `~/.bashrc` — при каждом новом интерактивном терминале. Неинтерактивный скрипт не читает ни одного из них: переменные окружения достаются ему в наследство от родителя.

Приглашение командной строки собирается из переменной `PS1`. Посмотреть текущее: `echo $PS1`. Пример: `PS1='\[\e[32m\]\u@\h\[\e[0m\]:\w\$ '` даёт зелёное имя пользователя. Более удобный путь — `starship` или `powerlevel10k`, они собирают приглашение сами.

Алиасы — не единственный способ сокращать команды. **Функции** умеют принимать аргументы:

```bash
mkcd() { mkdir -p "$1" && cd "$1"; }
extract() { tar -xf "$1"; }
```

Ещё полезно знать про `type -a ll`: команда покажет, чем именно является `ll` — алиасом, функцией, встроенной командой или файлом из PATH. Оболочка ищет в этом же порядке: алиас → функция → встроенная → файл.

Настройки для всех пользователей кладут в `/etc/profile.d/*.sh` — аккуратнее, чем править `/etc/profile`: каждое правило в своём файле.

</details>
