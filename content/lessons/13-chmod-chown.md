## Зачем это тебе

Классическая история: скачал скрипт, запускаешь — `Permission denied`. Или наоборот: положил файл с паролем в общую папку, и теперь его читает кто угодно. Обе ситуации лечатся двумя командами: `chmod` (какие права) и `chown` (чей файл).

Ещё один частый сценарий: ты создал ключ SSH, а система ругается, что «права слишком широкие» — ей нужно ровно `600`. Без понимания chmod ты тут просто застрянешь.

## Как это работает

### chmod: права в числах

`chmod` расшифровывается как *change mode* — «сменить режим доступа». Число состоит из трёх цифр: владелец, группа, остальные. Каждая цифра — сумма:

| Буквы | Число |
|:---:|:---:|
| `rwx` | 7 |
| `rw-` | 6 |
| `r-x` | 5 |
| `r--` | 4 |
| `-wx` | 3 |
| `-w-` | 2 |
| `--x` | 1 |
| `---` | 0 |

| Комбинация | Для чего |
|:---:|---|
| `644` | обычные файлы: я читаю и пишу, остальные читают |
| `755` | скрипты и папки: я делаю всё, остальные читают и входят |
| `600` | приватные файлы: только я (ключи, пароли) |
| `700` | приватные папки: только я |
| `777` | 🔴 всем всё — почти никогда не нужно |

```bash
chmod 755 deploy.sh        # числовой способ — самый частый
chmod 600 ~/.ssh/id_rsa    # закрыть ключ от всех
chmod -R 755 project/      # рекурсивно: пройти по всей папке
```

### chmod: права символами

Числа не всегда удобны, когда надо что-то *добавить*, не пересчитывая всё:

```bash
chmod +x deploy.sh      # добавить выполнение всем троим категориям
chmod u+x deploy.sh     # только владельцу (u = user)
chmod g-w notes.txt     # отнять запись у группы (g = group)
chmod o-r secret.txt    # отнять чтение у остальных (o = other)
```

Буквы: `u` — владелец, `g` — группа, `o` — остальные, `a` — все. Знаки: `+` добавить, `-` убрать, `=` поставить ровно это.

У `chmod +x` есть особенность: он добавляет `x` **всем трём категориям**, где уже есть право читать или выполнять. Для скрипта это нормально, для приватного файла — лишнее. Когда права важны, пиши явное число.

### chown: смена владельца

`chown` — *change owner*. Владельца может поменять только root: иначе любой присвоил бы себе чужие файлы, и права не значили бы ничего.

```bash
sudo chown alice file.txt            # сменить владельца
sudo chown alice:devs file.txt       # владельца и группу сразу
sudo chown -R www-data:www-data /var/www   # типичная настройка для сайта
chgrp devs file.txt                  # сменить только группу
```

### Типичные ошибки

- `chmod 644 script.sh` → скрипт выглядит нормально, но при запуске `Permission denied`: у него нет `x`. Нужно `755`.
- `chmod 777` «чтобы наверняка заработало» → заработает, и любой пользователь системы (и любая сломанная программа от твоего имени) получит право менять твой файл. Так делать не надо.
- `chmod` без прав → `Operation not permitted`: менять права на чужой файл может только root.
- `chown` без sudo → `Operation not permitted` по той же причине.
- `chmod` на папку без `-R` → поменялись права только у самой папки, а файлы внутри остались как были. Читай вывод ошибок внимательно: обычно в нём прямо сказано, чего не хватает.

## Итог дня

Сейчас ты умеешь:

- переводить буквы в числа и обратно (r=4, w=2, x=1) и понимать 644, 755, 600, 700;
- выдавать права через `chmod 755` и добавлять выполнение через `chmod +x`;
- менять права рекурсивно (`-R`) и объяснять, почему порядок важнее «наглухо 777»;
- называть, кому вообще разрешено менять владельца, и что для этого нужен sudo;
- читать `Operation not permitted` и понимать, что дело в чужих правах, а не в команде.

## Домашка

Здесь главная часть урока: 10 минут реальной практики. Всё делай в своей домашней папке, в отдельной подпапке `~/chmod-lab`.

1. Подготовь полигон: `mkdir -p ~/chmod-lab && cd ~/chmod-lab`.
2. Создай скрипт: `nano hello.sh` (`nano` — простой текстовый редактор прямо в терминале: открываешь файл, набираешь текст, сохраняешь), внутри две строки — `#!/bin/bash` и `echo "Привет"`. Сохрани.
3. Посмотри права: `ls -l hello.sh`. Увидишь `-rw-r--r--`.
4. Попробуй запустить: `./hello.sh` — получишь `Permission denied`. Прочитай текст ошибки: он прямо говорит про права.
5. Выдай права на запуск: `chmod +x hello.sh`, затем `./hello.sh`. Теперь работает.
6. Сделай строго: `chmod 755 hello.sh` и сравни `ls -l` с результатом шага 3.
7. Закрой файл от всех: `chmod 600 hello.sh`, попробуй `./hello.sh` — снова `Permission denied`. Верни 755.
8. Проверь рекурсию: `mkdir -p data/logs && touch data/logs/app.log && chmod -R 700 data && ls -l data data/logs`.
9. Почувствуй запрет: `chown root hello.sh` — получишь `Operation not permitted`, потому что без sudo ты не root.
10. Убери за собой: `cd ~ && rm -r chmod-lab`.

## <details><summary>🤓 Для любопытных</summary>

Символьный синтаксис умеет больше, чем кажется: `chmod u=rw,go=r file` — «поставить ровно это», `chmod a+r` — «добавить всем», `chmod -R o-w /srv` — рекурсивно отнять запись у остальных.

Справка по правам есть у самой команды: `man chmod` содержит и числа, и буквы, и особые биты. А посмотреть права без `ls`: `stat -c '%A %U %G %n' file` — печатает готовой строкой.

`chmod 1777 /tmp` — пример, где старшая цифра не «лишняя»: это особые биты (SUID/SGID/sticky), которые записываются четвёртой цифрой слева. В уроках 12 и 25 они разобраны подробнее.

Про umask и откуда берётся `644`/`755` по умолчанию: маска `022` вычитается из полных прав. Поставь `umask 077` — и все новые файлы будут доступны только тебе.

Если прав по пользователям не хватает, включай ACL: `setfacl -R -m g:devs:rwx project/`. Посмотреть, что получилось: `getfacl project/`. Скопировать ACL в новые файлы: флаг `-d` (default ACL).

</details>
